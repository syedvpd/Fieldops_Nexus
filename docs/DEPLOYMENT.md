| Production | Supabase Postgres 17, project `fieldops-nexus-prod-sg` (ref `rnfguqxrrbrjtqhwjlbo`, ap-southeast-1), schema `fieldops`, role `fieldops_app` | Render Key Value `fieldops-nexus-redis` (`red-db086bhsrm7s73eg3340`, Singapore, free). **Internal URL only** (reachable from Render services in the same workspace) | schema applied (32 migrations); no web/worker host yet: needs a Git remote |

Secrets live only in git-ignored files: `.env` (local compose, generated by `scripts/bootstrap_env.py`) and `.env.prod` (production values, generated by `scripts/bootstrap_prod_env.py`). Never paste them in chat, docs or commits.

## Local stack
```powershell
python scripts/bootstrap_env.py                     # once; writes .env
docker compose -p fieldops up -d --build            # db, redis, migrate, web, worker, beat, nginx
python scripts/smoke_stack.py http://localhost:8080  # browser-like smoke test
docker compose -p fieldops stop                      # stop, keep data
```
Create the Super Admin: see `docs/manual-tests/PHASE_0_MANUAL_TEST.md` step 1.

## Test database (isolated)
```powershell
docker run -d --name fieldops-test-pg -e POSTGRES_USER=fieldops -e POSTGRES_PASSWORD=<test-only> -e POSTGRES_DB=fieldops -p 55432:5432 postgres:16-alpine
$env:DJANGO_SETTINGS_MODULE="config.settings.test"; $env:DATABASE_URL="postgres://fieldops:<test-only>@localhost:55432/fieldops"; pytest -q
```
pytest creates and uses its own `test_fieldops` database. Never point tests at Supabase.

## Production database (Supabase)
Done once (idempotent scripts, never drop anything):
1. `scripts/bootstrap_prod_env.py` -> `.env.prod` (random Django secret, random `fieldops_app` password, admin URL from `SUPABASE_ADMIN_PASSWORD`).
2. `scripts/provision_supabase.py` -> role `fieldops_app`, schema `fieldops` owned by it, `search_path` pinned.
3. `manage.py migrate` with `DATABASE_URL` from `.env.prod` and `config.settings.prod`.
Routine: load `.env.prod` into the shell and run `python manage.py migrate --noinput` for every new migration; the app runs as `fieldops_app` only.
Security verified: `anon`, `authenticated`, `service_role` have no access to schema `fieldops`; audit trigger `audit_auditlog_immutable` is enabled.
Connection: direct host `db.<ref>.supabase.co:5432` works from IPv6-capable hosts; Render services typically need the Supabase **pooler** string (session mode) with user `fieldops_app.<ref>`.

**Recommended hardening (Team Lead):**
- Rotate the `postgres` password to a long random value (the current admin password is weak and the database is internet-reachable) and update `SUPABASE_ADMIN_DATABASE_URL`.
- Delete the paused wrong-region project `fieldops-nexus-prod` (ap-south-1) in the Supabase dashboard.
