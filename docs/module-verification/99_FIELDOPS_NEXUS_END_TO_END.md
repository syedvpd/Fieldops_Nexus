# FieldOps Nexus: the whole product in one document

*For explaining the system to the client. Plain language. Technical detail is in the module guides.*

## 1. What it is
One web application (not 15 tools) for companies that own equipment and must keep it running: **Enterprise Asset, Maintenance and Field Service management**. It is **multi-tenant**: many companies use the same system and can never see each other's data.

## 2. Who uses it
| Person | What they do |
|---|---|
| Platform Super Admin | Creates companies, invites each company's owner |
| Organization Owner / Admin | Sets up sites, users, roles, SLA rules, contracts |
| Operations Manager | Watches incidents, approves, creates and assigns work orders |
| Maintenance Planner | Builds PM plans and schedules |
| Supervisor | Reviews finished jobs, closes or sends back |
| Technician | Does the job on site (phone-friendly) |
| Stores Manager | Spare parts and stock |
| Asset Manager | Equipment register, labels |
| Service Manager | Contracts, SLA, client portal |
| Auditor | Read-only evidence and exports |
| Client | Raises and follows service requests in a simple portal |

## 3. The story from start to finish (how modules connect)
1. **Setup (M01):** Super Admin creates the company; the owner adds **sites and locations** and **invites staff** with roles (some limited to certain sites).
2. **Equipment (M02, M03):** assets are registered per site with documents, meters and a parent/child structure. **Labels (M12)** with QR codes are printed and stuck on the machines.
3. **Prevention (M04):** planners schedule routine maintenance. The system **creates the work orders by itself** when due.
4. **Problems (M05, M13):** staff scan a label and report, or a client raises a request. An **SLA clock (M11)** starts and warns/escalates by in-app message and email.
5. **Decision:** a manager triages, approves/rejects, and creates a **work order (M06)**. **Coverage (M10)** says whether warranty/AMC applies.
6. **Execution (M07, M08, M09):** the technician sees "My Jobs", follows a **checklist**, records labor, uses **stock** (reserved → issued → consumed/returned), adds evidence, completes.
7. **Control:** the supervisor reviews and closes (or returns for rework). The client confirms resolution.
8. **Insight and proof (M14, M15):** dashboards show MTTR, downtime, SLA breaches, PM compliance, parts use; the **audit trail** proves who did what and can be exported (CSV/Excel/PDF).

## 4. The five mandatory state machines (HPE 8.1)
Each has a step-by-step guide in `workflows/`: **W1** Service Request · **W2** Work Order · **W3** Preventive Maintenance · **W4** Part Request · **W5** Asset status.

## 6. What makes it safe (say this to the client)
- **Company isolation:** every record belongs to one company; cross-company access returns "not found".
- **Role + site permissions** are enforced on the server, not just hidden buttons.
- **State rules:** a request or work order cannot skip steps, and closing needs real labor/evidence/checklists.
- **Audit:** append-only; exports are audited.
- **Secure labels:** QR codes are random tokens; scanning never bypasses login.
- **Email and scheduling are real:** invitations and SLA breach alerts go out by email (Brevo); a background scheduler generates PM work orders and checks SLAs every minute.

## 7. How it runs
Web app (Django) + background worker and scheduler (Celery with Redis) + PostgreSQL (Supabase). Live on Render Free at https://fieldops-nexus-web.onrender.com (free tier sleeps after idle; a 5-minute keep-alive ping reduces that). Daily and weekly jobs are automatic.
